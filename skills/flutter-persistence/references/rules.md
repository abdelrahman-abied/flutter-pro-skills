# PERSIST rules: what the checker reports, and why

`scripts/check_persistence.py` is static and read-only. It needs only the
Python standard library and no `pub get`. Every hit is a candidate: read the
code before you call a finding `confirmed`. Each rule lists the false
positives it knows about and how to suppress a deliberate case.

The checker judges what the architecture checker can't see: the SQL text,
schema versions, migration strategies, Hive type ids, database lifetimes and
write loops. Where a concern already has an owner in the suite, PERSIST
cross-references it instead of reporting it again (section 4).

## 1. How the checker reads the project

- **Scope.** Every `.dart` file under `lib/`, minus generated files
  (`*.g.dart`, `*.freezed.dart`, `*.drift.dart`, `*.steps.dart`, files with a
  `GENERATED CODE - DO NOT MODIFY` banner) and barrels. A drift database file
  whose comment says "Generated by drift_dev when running build_runner" is
  *not* generated and is scanned, even if `arch_check` leaves it out of
  `files[]`.
- **Layers and roles** come from `../flutter-architecture/scripts/arch_check.py
  --json` (`files[]`). It reuses `$FPS_ARCH_JSON` when `dart-flutter-review`
  already ran it. Without the sibling skill, a path-based fallback is used and
  the `classification:` line says so.
- **`di` files** (only providers or registrations) are composition-root code.
  The checker reads them only for PERSIST-006's provider-lifetime check,
  because that is exactly where a database's lifetime is decided.
- **Constants** are resolved across the project: top-level and `static`
  `const`/`final` names, `k`-prefixed and `SCREAMING_CASE` names, numeric
  types, and `for`-in variables over a constant collection all count as
  constant. That is how `$kNotesTable` or a `List.filled(n, '?').join(', ')`
  placeholder list stays quiet.
- **Placement notes.** Each finding's `note` ends with the fix location for
  the detected profile (`MVN: …`, `MVVM: …`, `Bloc: …`, `Riverpod: …`,
  `Provider: …`, `GetX: …`, plus `Clean: …` when the project has domain and
  data layers). `--profile` overrides the detected pattern.

## 2. Rules

### PERSIST-001 sql-built-from-strings

**High** when the value is a string parameter or `controller.text` · **Low**
when the value can't be traced, or a private helper only ever receives
constants but the value sits in a quoted value position · all profiles

**Detects:** a string literal that starts like SQL (or any string passed to
`rawQuery`, `rawInsert`, `rawUpdate`, `rawDelete`, `customSelect`,
`customStatement`, `customUpdate`, `customInsert`) or a sqflite `where:` /
`having:` argument, built with `$x`, `${expr}` or `+ x`. One finding per
statement, for the worst value in it. Parameters are traced to their call
sites: a private `_tableExists(db, 'puzzle')` that only ever receives
literals stays Low.

**Why:** a quote, `--` or `;` in the value changes the statement. On a
device that's both a crash on the first apostrophe ("O'Brien") and SQL
injection when the value comes from a deep link, a server response or a
search box. Bound parameters are also faster, because SQLite can cache the
prepared statement.

```dart
// Bad
Future<List<Map<String, Object?>>> search(String q) =>
    _db.rawQuery("SELECT * FROM notes WHERE title LIKE '%$q%'");

// Good (sqflite)
Future<List<Map<String, Object?>>> search(String q) =>
    _db.rawQuery('SELECT * FROM notes WHERE title LIKE ?', ['%$q%']);

// Good (drift)
Selectable<QueryRow> search(String q) => customSelect(
      'SELECT * FROM notes WHERE title LIKE ?',
      variables: [Variable.withString('%$q%')],
      readsFrom: {notes},
    );
// Better (drift): no SQL string at all
(select(notes)..where((n) => n.title.like('%$q%'))).get();
```

Identifiers (table and column names) can't be bound. Check them against an
allow-list (`const {'title', 'created_at'}.contains(column)`) before you
interpolate.

**Not reported:** constants, numbers, `DateTime.toIso8601String()`,
`'?'` placeholder lists, `PRAGMA` statements with a traced or framework value
(`PRAGMA user_version = $to` in `onUpgrade`, `PRAGMA key = '$escapedKey'`
built from a constant), and a pass-through `run(String sql, args)` helper.
**False positives:** a value checked against an allow-list in another
function. Suppress with the reason:
`// persist-ignore: PERSIST-001 column is checked against kSortColumns`.
**Profiles:** the fix lives in the source/data provider/service that owns the
SQL. Repositories and logic never build SQL.

### PERSIST-002 drift-schema-without-migration

**High** · all profiles

**Detects:** a `@DriftDatabase` class (`extends _$X`, `extends $X` or
`GeneratedDatabase`) whose `schemaVersion` resolves to a number above 1 and
that has no `migration` getter, or whose `MigrationStrategy(...)` has no
`onUpgrade:`.
**Why:** drift's default `onUpgrade` throws. Every user who updates the app
gets a database that won't open, while fresh installs (and your emulator)
work fine.

```dart
// Bad
@override
int get schemaVersion => 3;

// Good: generated with `dart run drift_dev make-migrations`
@override
int get schemaVersion => 3;

@override
MigrationStrategy get migration => MigrationStrategy(
      onUpgrade: stepByStep(
        from1To2: (m, schema) async => m.addColumn(schema.notes, schema.notes.dueDate),
        from2To3: (m, schema) async => m.createTable(schema.tags),
      ),
      beforeOpen: (details) async => customStatement('PRAGMA foreign_keys = ON'),
    );
```

**False positives:** a migration getter that returns a strategy built
elsewhere (a field) is accepted when it contains no `MigrationStrategy(`
call. Versions computed at runtime aren't resolved and aren't reported.
See `migrations.md` §1.

### PERSIST-003 sqflite-version-without-upgrade

**High** · all profiles

**Detects:** `openDatabase(...)` or `OpenDatabaseOptions(...)` with
`version:` resolving above 1, not `readOnly: true`, and no `onUpgrade:`.
**Why:** `onCreate` runs only on a fresh install. Upgraded installs keep the
old schema, and the first query that touches a new column fails.

```dart
// Bad
openDatabase(path, version: 3, onCreate: _createV3);

// Good
openDatabase(
  path,
  version: 3,
  onCreate: (db, v) => _createLatest(db),
  onUpgrade: (db, oldVersion, newVersion) async {
    final batch = db.batch();
    if (oldVersion < 2) _addTagColumn(batch);
    if (oldVersion < 3) _createAuthorsTable(batch);
    await batch.commit(noResult: true);
  },
);
```

**False positives:** a deliberately destructive cache database that deletes
the file on a version change. Say so with
`// persist-ignore: PERSIST-003 cache only, recreated by deleteDatabase in onConfigure`.

### PERSIST-004 hive-type-id-collision

**High** · all profiles

**Detects:** two `@HiveType(typeId: N)` annotations, or `TypeAdapter`
subclasses with `typeId = N` / `get typeId => N`, that share `N` across the
project (literals and `const` names are resolved). Reported on every use after
the first; the note names the first.
**Why:** `registerAdapter` throws "There is already a TypeAdapter for typeId",
or, with adapters registered conditionally, data written as one type is
decoded as the other.
**Fix:** a unique id per type, recorded in one `hive_type_ids.dart`, and never
reused after a type is removed. hive_ce's `@GenerateAdapters` assigns ids for
you.
**False positives:** two adapters that are never registered in the same
isolate (rare). Rename one id anyway.

### PERSIST-005 hive-field-index-collision

**High** · all profiles

**Detects:** two `@HiveField(N)` with the same `N` inside one `@HiveType`
class.
**Why:** Hive stores fields by index. Two fields with one index overwrite
each other, and old records decode into the wrong field.
**Fix:** the next unused index. When you delete a field, keep its index
retired (a comment `// 2: removed (was nickname)` helps the next person).

### PERSIST-006 database-opened-per-use

**Medium** · all profiles

**Detects** a construction of a project drift database class (any
constructor, including named ones), `Isar.open`/`openSync` or ObjectBox
`openStore`:
- inside an auto-disposed provider (`@riverpod` without
  `keepAlive: true`, `Provider.autoDispose`, an `@riverpod` notifier);
- registered with get_it `registerFactory`;
- inside an ordinary method, `build()` or callback, as a local value that
  isn't stored.

**Not reported:** top-level and `static final` instances, field
initializers, constructors, `??=` memoisation, assignment to a field or to
provider state (re-opening after a restore), non-autoDispose providers,
`registerLazySingleton`/`registerSingleton`, `Get.put`, `main()`, methods named
`init*`/`open*`/`create*`/`setup*`/`connect*`, static factories, and
background-isolate entry points (`@pragma('vm:entry-point')`, `*Isolate*`,
`*Background*`, `*Worker*`), which need their own connection.

**Why:** drift warns at runtime when two instances open one file: each has
its own connection and stream-query store, so `watch()` on one never sees
writes through the other, and concurrent writes fail with "database is
locked". An auto-disposed provider closes the database whenever no widget
watches it and reopens it on the next read.

```dart
// Bad
@riverpod
AppDatabase appDatabase(Ref ref) => AppDatabase(driftDatabase(name: 'app'));

// Good
@Riverpod(keepAlive: true)
AppDatabase appDatabase(Ref ref) {
  final db = AppDatabase(driftDatabase(name: 'app'));
  ref.onDispose(db.close);
  return db;
}
```

Hive's `openBox` and sqflite's `openDatabase` aren't reported: both return
the already-open instance for the same name or path (`singleInstance: true`
is sqflite's default). See `placement-by-architecture.md` §2.

### PERSIST-007 writes-in-loop-without-transaction

**Medium** · all profiles

**Detects:** a `for`, `await for` or `.forEach` loop that awaits a drift
write (`into(t).insert`, `insertOnConflictUpdate`, `update(t).write`,
`delete(t).go()`, `insertOne`, `deleteOne`, `replace`) or a sqflite write
(`db.insert('t', …)`, `update`, `delete`, `rawInsert`, `rawUpdate`,
`rawDelete`) in a file that imports drift or sqflite, with no enclosing
`transaction(`, `batch(`, `writeTxn(` or migration callback (`onCreate`,
`onUpgrade`, `from1To2`, …, which already run in a transaction). Receivers
named `batch`/`txn` are skipped.
**Why:** each statement is its own transaction, so 1,000 rows means 1,000
journal syncs (seconds instead of milliseconds), and a crash or a thrown
error in the middle leaves half the data written.

```dart
// Bad
for (final n in notes) {
  await db.into(db.notes).insert(n.toCompanion());
}

// Good
await db.batch((b) => b.insertAll(db.notes, notes.map((n) => n.toCompanion())));
// or, when each step needs the previous result
await db.transaction(() async {
  for (final n in notes) {
    await db.into(db.notes).insert(n.toCompanion());
  }
});
```

**False positives:** a loop inside a function that every caller already wraps
in a transaction. Suppress it with that reason, or move the transaction into
the function. Hive `put` loops aren't reported (use `putAll` anyway).

### PERSIST-008 drift-migrations-untested

**Low** · all profiles

**Detects:** a drift database with `schemaVersion > 1` and an `onUpgrade`
strategy, in a project with no `drift_schemas/` folder, no
`drift_schema_vN.json` files, no generated `test/**/schema_vN.dart` files and
no test using `SchemaVerifier`. Reported once per database.
**Why:** a migration is the only code that runs once, on real user data, with
no second chance. Drift can verify each `fromNToM` step against the exported
schema of both versions, but only if the schemas were exported when each
version shipped.
**Fix:** configure `build.yaml` (`databases: app: lib/data/db/app_database.dart`)
and run `dart run drift_dev make-migrations` before each release that bumps
the version. It exports the schema, writes `*.steps.dart`, and generates a
migration test. See `migrations.md` §1.

### PERSIST-009 sensitive-store-unencrypted

**Medium** for health, medical, diagnosis, prescription, SSN, passport,
biometric, credit card, card number, IBAN, bank account · **Low** for payment,
salary, insurance, banking · all profiles

**Detects:**
- `Hive.openBox`/`openLazyBox` whose name or type is one of those, without
  `encryptionCipher:`;
- a drift `Table` class or a database file name (`driftDatabase(name:)`,
  `openDatabase('….db')`, `NativeDatabase`) with one of those names, when the
  project has no database encryption (no `sqlcipher_flutter_libs`,
  `sqflite_sqlcipher`, `sqlite3mc`, and no `PRAGMA key`);
- a `@HiveType` class with one of those names when no box anywhere uses
  `encryptionCipher`.

**Why:** app-sandbox files are plain text to anyone with a rooted device, a
device backup or a forensic image. Health, identity and card data carry legal
duties (GDPR special categories, HIPAA, PCI DSS) that "it's only on the
phone" doesn't meet.

```dart
// Good (Hive): key generated once and kept in secure storage
final key = await _secureKeys.hiveKey(); // List<int> from Hive.generateSecureKey()
final box = await Hive.openBox<MedicalRecord>('medical_records',
    encryptionCipher: HiveAesCipher(key));
```

Tokens and passwords in any store are **SEC-001**
(`flutter-secure-defaults`), not this rule.
**False positives:** a `payments` box that only holds a payment *status* or a
masked last-4. That's why payment-like names are Low. Suppress with the
reason.

## 3. Reading-level findings (PERSIST-<slug>)

The checker can't see these. Look for them when you review persistence code.

| ID | Severity | Look for | Fix |
|---|---|---|---|
| PERSIST-destructive-migration | High | `onUpgrade` that drops and recreates tables holding user data, or `deleteDatabase` on a version change for a non-cache store | per-step migrations that keep rows; copy into a new table and rename |
| PERSIST-offline-write-lost | High | a write that fails offline and is dropped (no outbox), or an optimistic UI update with no rollback | write locally first, enqueue an outbox row, sync later (`caching-and-offline.md` §4) |
| PERSIST-persistence-type-leak | Medium | drift rows, companions, `HiveObject`s or Isar collections returned past the repository or used as UI state | map to domain entities in the repository (`placement-by-architecture.md` §3); compare ARCH-006/107 |
| PERSIST-no-cache-policy | Medium | a cache with no TTL, no invalidation on writes and no size bound | cache-aside with `fetchedAt`, invalidation in the same repository, an LRU or row cap (`caching-and-offline.md` §1–2) |
| PERSIST-sync-without-conflict-policy | Medium | two-way sync that overwrites whichever side wrote last, silently | an explicit policy: server wins, last-writer-wins by server timestamp, or field merge |
| PERSIST-non-idempotent-retry | Medium | retried POSTs from an outbox with no idempotency key | a client-generated key per operation, sent as `Idempotency-Key` |
| PERSIST-key-rename-without-migration | Medium | a renamed shared_preferences key, Hive box or file with no read-old/write-new step | a one-time migration keyed by a stored schema version (`migrations.md` §4) |
| PERSIST-pii-in-key | Medium | emails, phone numbers or names in cache keys, box names or file names | key by an opaque user id or a hash |
| PERSIST-prefs-as-database | Low | lists of records, JSON blobs or growing histories in shared_preferences | a table or box; shared_preferences is for small settings (`choosing-storage.md` §2) |
| PERSIST-connectivity-as-truth | Low | skipping a request because `connectivity_plus` says "none", or assuming "wifi" means online | try the request, treat failure as offline; connectivity is a hint |
| PERSIST-legacy-prefs-api | Info | new code on `SharedPreferences.getInstance()` | `SharedPreferencesAsync` or `SharedPreferencesWithCache` (shared_preferences ≥ 2.3) |

## 4. Not checked here (cross-references)

| Concern | Owner | Why PERSIST stays out |
|---|---|---|
| tokens, passwords, secrets in SharedPreferences, Hive, GetStorage, drift or sqflite columns | SEC-001 (`flutter-secure-defaults`) | one owner per finding; PERSIST-009 covers *other* sensitive data |
| tokens held in global or UI state | SEC-010 | |
| logout leaves the database, boxes or caches behind | SEC-no-logout-wipe | the wipe list is in `placement-by-architecture.md` §5 |
| `SharedPreferences.getInstance(` / `openDatabase(` inside widgets | ARCH-101 | a layer rule |
| storage packages imported by views, widgets or logic | ARCH-005 / ARCH-007 / ARCH-012 | a layer rule |
| storage packages imported by the domain layer (`@HiveType` entities) | ARCH-003 | a layer rule |
| presentation importing DTO/table files; repositories returning `Map`s | ARCH-006 / ARCH-107 | the reading-level PERSIST-persistence-type-leak adds row types |
| swallowed or unmapped storage errors (`SqliteException`, `HiveError`) | ERR-001 / ERR-002 / ERR-004 / ERR-007 | PERSIST never re-detects catches |
| `android:allowBackup`, backup exclusion rules, Keychain accessibility | `flutter-security-audit` (STO-ALLOWBACKUP) | platform configuration |
| JSON decode or big queries on the UI isolate | `flutter-performance` (PERF) | |
| stream subscriptions to `watch()` never cancelled | AP-stream-subscription-in-widget / UI-lifecycle | |

Run on the suite's shared calibration pool (§24 of the suite contracts).
Each example folder with its own `pubspec.yaml` was run separately,
including the nested bloc packages (`flutter_todos/packages/*` and others).
Every hit was read and judged.

The lichess hit is `_tableExists(db, table)` putting `table` into
`name='$table'`. Every call passes a constant, so it is Low, and it is a true
positive at that grade: the value sits in a quoted value position and should
be bound (`WHERE type = 'table' AND name = ?`).

**False-positive causes fixed.** "Run" means a checker run reported it;
"reading" means the calibration code was read before the rule shipped and the
pattern was handled up front. Each cause has a `calib_*` regression fixture
plus a test that the related true positive still fires.

| Cause | Seen in | Found by | Fix | Fixture |
|---|---|---|---|---|
| drift modular generation writes `*.drift.dart` files without a "GENERATED CODE" banner; their `customSelect('… ${generatedpredicate.sql}')` was reported (low ×2) | drift `examples/modular` | run | `*.drift.dart` and `*.steps.dart` are generated | `calib_drift` |
| `PRAGMA user_version = $to` in `onUpgrade` (a framework-supplied int; PRAGMA can't take bound parameters) was reported (low ×1) | immich | run | PRAGMA statements report only parameter or input values | `calib_immich` |
| `PRAGMA key = '$escapedKey'` from a constant password | drift `examples/encryption` | reading | locals are traced to their initializer | `calib_drift` |
| `UPDATE $table SET …` inside `for (final MapEntry(key: table, …) in _constMap.entries)` | immich | reading | `for`-in variables over constant collections are constant | `calib_immich` |
| `IN ($_themeKeysPlaceholders)` built with `List.filled(n, '?')` at top level | lichess | reading | top-level `final` and `'?'` placeholder lists are constant | `calib_lichess` |
| a private helper whose `String` parameter only ever receives literals would be High | lichess | reading | call sites are traced; constant-fed values are Low, and only in a value position | `calib_lichess` |
| re-opening the database into provider state after `close()` during a restore | drift `examples/app` | reading | assignment to a field or `.state` is a re-open, not a second instance | `calib_drift` |

**False negatives fixed:** immich's `class Drift extends $Drift` (drift's
newer generated base without the underscore) wasn't recognised as a database;
and `arch_check` leaves out drift's `database.dart` because of its "Generated
by drift_dev when running build_runner" comment, so the checker now does its
own generated-file detection. Both are covered by `calib_immich` and
`calib_drift`.
